# 预测服务的进程、数据与模型复用

网页主进程只加载服务与存储代码，数值库和模型仅在一个常驻预测子进程中加载。每次更新向该进程发送一个请求，完成后等待下一轮；关闭网页服务会终止并回收该子进程。子进程异常退出后，下一轮重新启动。数值库仍使用单线程。独立 CLI 命令继续执行一次后退出。

自动训练关闭时，更新流程跳过训练历史读取，状态阶段使用 `model_loading`。反馈只读取曾签发预测的活动曲线；本期预测只读取当前活动曲线。排名、完成时间和活动范围在 SQL 查询中筛选，再解码 JSON；密集采样起点、前缀截断和终分质量规则继续执行。显式启用训练的旧研究入口仍读取期初合格历史。

模型缓存限定在预测会话中，默认只保留当前一个模型包。替换时先释放旧对象，再加载新版本；不会预加载备用版本。Context 包只保留推理依赖的模型、预处理器、特征设计、历史摘要和校正记录，不在内存保留训练诊断与 OOF 数组。首次使用执行完整的 manifest、SHA-256、源码、软件、数据政策、时间约束及技术重放校验；技术重放加载的预处理器和模型对象直接用于后续预测。后续使用检查文件清单、inode、类型、大小、纳秒修改时间和状态变更时间，并检查相关源码与兼容注册文件。任一变化使缓存失效并重新执行完整校验。显式的模型发布和安装校验继续使用完整校验。

当前活动元数据按四个 JSON 文件的状态缓存，只保留一份，文件变化后重新读取。每次预测使用独立的特征词表和日历缓存。按用户指定的单版本部署方式，安装新版后下一轮使用当前指针指定的模型，活动不再依赖已删除的旧权重；旧绑定和已签发预测保存在账本供追溯，校正快照保留。新版仍须满足密集时期数据政策及开始前历史约束。固定研究协议中的期初模型约束继续执行。

`production/layout-compatibility.json` 保留原有迁移登记，并增加已发布源码集合到本次源码集合的完整映射。兼容登记用于这次推理资源复用修改；不修改已发布模型的 manifest、工件或权重，也不接受未登记的源码变动。

回归入口：`uv run --locked --group research python -m unittest discover -s tests -p test_inference_reuse.py -v`。测试覆盖预测逐值一致、每个模型工件只反序列化一次、完整校验复用、缓存失效、模型淘汰与重新校验、元数据刷新、未来信息拒绝、无关历史隔离，以及子进程复用、退出恢复和停止回收。

离线性能核验可运行 `uv run --locked --group research python tests/profile_inference_reuse.py --state runtime/live`。脚本将数据库、元数据和模型复制到临时目录，只在副本上执行固定时刻的两轮预测；输出耗时、加载次数和曲线读取数量，不启动网页或联网同步。首次更新与缓存更新的耗时受操作系统文件缓存影响，不作为多次测量的性能统计。

该修改属于部署性能修复，不生成新的模型准确率结果。真实性能核验和完整回归记录见同目录 `inference-reuse-verification.json`。
