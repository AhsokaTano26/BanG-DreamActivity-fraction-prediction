# 2026-11-19 目录与 uv 迁移核验

本次将研究模块移至 `training/analysis/`，把生产拟合及专用准备函数移至 `training/model_fit.py`，通过 uv 的可编辑安装保留 `analysis.*` 等序列化导入名。数据、原始运行目录和已训练模型包继续留在原位置。

## 指纹兼容规则

`production/layout-compatibility.json` 登记此次迁移前的完整源码指纹集合和迁移后的完整集合（含包初始化文件，共22个受追踪文件）。`production/source_compat.py` 仅在两套字典逐项相等时接受这一已审阅迁移；增加、移除或改动受追踪文件均会使该映射失效。新训练的包直接记录新源码集合。

旧模型的原始身份、manifest、权重、预处理器及源码副本未改写。加载时仍验证 manifest 封印、完整工件集合及每个 SHA-256、原 Python 与依赖版本、密集采样政策、严格结束时间约束和逐值技术预测重放。兼容注册没有放宽这些检查。

技术重放按案例身份对齐并拒绝非有限值；跨 CPU 的浮点比较采用相对容差 `1e-12`、绝对容差 `1e-8 EP`。在一亿分量级，相对容差对应 `0.0001 EP`。测试明确拒绝一分的变化。容差只用于加载校验，模型文件、参考值和实际预测均保留原值；同环境拟合前后的序列化比较仍要求完全一致。

## 数值与评测范围

迁移前已在原环境验证生产包，并保存19个技术预测。迁移后逐项重放，比较对象是同一模型、同一盲前缀与同一预处理。技术重放用于判断目录和代码抽取是否影响计算；其输入为既有模型包中的技术样本，不能作为新增训练精度或独立测试成绩。

模型关键版本保持 Python 3.14.8、CatBoost 1.2.10、NumPy 2.5.4、pandas 3.1.1、scikit-learn 1.9.1、SciPy 1.18.1、XGBoost 3.4.1、joblib 1.6.0。uv 锁定其余传递依赖，并将研究依赖置于可选组。

## 运行边界

根 `uv run app.py` 和 Docker 网页周期均关闭自动拟合，即使原配置曾启用训练。网页继续保存已发出的预测和合法终分反馈。训练通过 `uv run training/train.py fit` 显式执行，模型安装与网页框架构建继续分别管理。

新入口的目录隔离、原始数据库只读、日期筛选、训练输出、完整指纹比较、源目录保护、固定协议及旧方法的回放均由测试和迁移核验记录检查。历史测试队列和曾反复使用的验证集保留原来的探索性解释。
