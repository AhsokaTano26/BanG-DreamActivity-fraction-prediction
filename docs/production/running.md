# 手动运行预测

2026-11-19起网页入口为根目录的 `app.py`，单线预测保留 `forecast.py`。依赖由 uv 管理，首次运行先执行 `uv sync --locked`。此前的macOS定时任务已暂停，模型、数据和历史预测记录保留。下面的两个命令都由用户主动执行。

## 一次预测

在项目根目录运行：

```bash
uv run --locked python forecast.py --rank 1000
```

默认识别正在进行的国服活动，只同步所选分数线并用已训练的模型预测，然后退出。支持19档：T10、T20、T30、T40、T50、T100、T200、T300、T400、T500、T1000、T1500、T2000、T3000、T4000、T5000、T10000、T20000、T30000。

```bash
uv run --locked python forecast.py --rank T2000
uv run --locked python forecast.py --rank 1000 --json
uv run --locked python forecast.py --rank 1000 --offline
```

终端显示活动、当前分数、预测终分、活动进度和实际观测时间。一次预测不拟合模型，不启动网页或定时任务。网络更新异常时，仅在缓存仍通过质量和时效检查的条件下预测，并提示使用缓存；超过60分钟的观测不用于生成新预测。没有进行中的活动或缺少足够观测时会明确说明，不生成数值。退出码0表示生成预测，2表示无可用预测或任务忙，1表示运行错误。

每次实际发出的预测进入原有账本；单线输出另存 `runtime/live/requests/latest_t1000.json` 等文件，不覆盖全部排名的结果。服务只使用当前安装的模型，新版安装后在下一轮生效，旧绑定会归档；校正状态仍按期初可用反馈建立。首次部署尚无权重或历史时，先安装模型包，再运行网页完成数据初始化。

## 持续预测与网页

```bash
uv run --locked app.py
```

打开 <http://127.0.0.1:8765>。服务启动后立即进行一轮更新，之后每轮完成后等待900秒再更新；计算任务始终串行。网页每15秒读取已保存的结果，点击“刷新页面”也只读取结果，不另启动训练。

更新复用一个常驻预测子进程及已校验模型。自动训练关闭时跳过训练历史读取，按需要查询本期曲线和已签发预测的活动反馈；模型、源码或活动元数据文件变化时，相应缓存失效。实现与核验见[资源复用说明](inference-reuse.md)。

网页顶部显示当前活动名称、官方横幅、活动类型、国服起止时间与日服开始时间，并显示活动进度和结束倒计时。可选择排名、查看当前与预测分数、观测时间及19线结果表。

桌面宽屏采用三列等高布局：左侧显示活动与预测摘要，中间显示预测记录和图表，右侧显示全部分数线。中间图表纵向填满剩余空间，三列顶部和底部对齐。点击右侧任意一行即可切换排名，所选行与左侧选择器保持同步。右侧列表可以独立滚动；较窄桌面使用两列，手机上下排列。下拉菜单、按钮、表格与消息使用统一的蓝色控件样式，选择菜单支持方向键、Home/End、回车、空格、Escape及输入排名定位。

活动选择器列出本地已有的密集采样时期活动，默认显示正在进行的活动。历史模式提供全部可用排名曲线、已核实终分及实际保存的最后预测；没有上线预测时显示“该活动没有上线预测记录”，终分未核实时显示最后观测分数。不会用当前模型回算历史活动并将结果当成当时的上线预测。真实上线账本从329期开始保存。

部分终分在结束后五分钟内上报。历史图表将经核实终分作为活动结束状态端点，并在图注保留实际上报时间；API单独返回该终分与原时刻，普通观测点仍保持原采样时刻。

图表横轴固定覆盖活动开始至结束，纵轴从零开始。实线面积使用生产缓存中的真实分数观测，包括首次上线预测以前的观测；虚线使用实际发出的终分预测记录，最后一笔预测水平延伸至活动结束。该延伸表示当前终分估计，不表示未来真实分数走势，也不补造早期预测。数据陈旧、更新异常和历史支持不足都会显示提示。

活动结束后，历史图按进度25%、50%、75%、90%，结束前24、6、1小时及末次预测共8个时点进行核对。各阶段仅选择目标时点前1小时内、当时已经发布的最近观测预测；同一观测时间也只能使用该时点之前已发布的修订。末次预测独立列出，缺失记录显示原因，不事后重算或用后来的预测补齐。

取得已核实的正终分后，图上显示实际终分参考线和各核对点的误差标记；悬停、点选标记或用键盘选择可查看该点的真实预测值、目标时刻和发布时间。展开“各时点预测与误差”查看完整对照，同一实际预测被多个阶段引用时图上合并标记。误差为 `(预测终分 - 实际终分) / 实际终分 × 100%`，正值表示高估，负值表示低估；右侧全部分数线表保留末次预测误差。未核实终分、终分无效或没有上线预测记录时，不给出误差。核对只读保存的预测和终分；终分修订在下一次页面刷新时反映，不改写已签发记录。

首次显示图表时，曲线从活动开始播放至最新观测。切换活动或排名时，中间内容以约220毫秒的淡入和轻微位移过渡，左侧保持原位；自动刷新不触发切换动画，也不重播首次曲线动画。悬停或手机点选可查看同一时刻的两条曲线读数；两观测点之间按图中直线计算，真实曲线之外显示暂无观测，预测延伸段标明当前估计。图表也支持方向键、Home/End和Escape，并遵循系统减少动态效果设置。

页面每15秒读取一次已保存的结果，后台默认每15分钟向数据源取数；按钮“刷新页面”重新读取当前结果。左侧分别显示实际观测时间、最近取数与下次取数时间。上游尚无新观测时，分数和预测可以保持不变。

持续模式同步数据、核实已结束活动的终分并更新误差反馈。模型拟合由 `uv run training/train.py fit` 显式执行，安装新权重后下一轮采用该版本。所有建模与反馈遵守2024-01-29 13:00起点和开始前历史约束。历史探索性测试成绩不代表当前生产模型的保证精度。

按 **Ctrl+C** 结束；SIGTERM及终端关闭信号也会清理本服务拥有的计算子进程。结束后没有周期更新，网页地址停止响应。此命令不安装launchd任务。

可选参数：

```bash
# 修改端口、每30分钟更新
uv run --locked app.py --port 8766 --interval 1800

# 离线运行；调用已安装权重
uv run --locked app.py --offline
```

默认只监听本机。`--host`允许显式指定监听地址，适合另行部署时使用；当前页面和API没有用户登录机制。

## 文件与状态

- `runtime/live/latest.json`、`latest.csv`：持续模式保存的全部排名结果。
- `runtime/live/requests/latest_t<rank>.json`：单次模式结果。
- `runtime/live/state.sqlite3`：实际预测、期初模型和终分反馈。
- `runtime/live/models/versions/`：不可覆盖的模型版本。
- `runtime/live/web_worker_errors.log`：持续模式计算失败时的诊断信息。

```bash
uv run --locked python -m production.selected_cli status
```

该命令同时报告旧系统定时任务状态。手动网页服务运行于执行 `uv run app.py` 的终端；它的运行状态显示在网页中。`production.selected_cli install`会安装另一种系统后台运行方式，日常两种模式都不需要执行它。
