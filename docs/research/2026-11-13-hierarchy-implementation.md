# 类型与乐队层级收缩：固定实现说明

本实现是 `2026-11-13-innovation-experiments.md` 的任务 3。候选在真实验证／测试评分前确定；开发只使用人工构造数组，未读取验证或测试答案、SQLite、完整验证／测试曲线，也没有根据模型分数追加候选。

## 固定候选

| 配方 | 输入与校正 |
| --- | --- |
| `hierarchy_static_context` | 单线 CatBoost，加训练词表生成的类型 one-hot 和乐队比例列 |
| `hierarchy_additive_shrinkage` | 单线 CatBoost，加严格时序 OOF 残差拟合的全局项、类型项、乐队比例项 |
| `hierarchy_phase_shrinkage` | 同一骨干与 OOF 过程，加类型／乐队项与两个固定阶段函数的交互 |

三者 CatBoost 都固定为 600 trees、depth 5、learning rate 0.035、L2 12、seed 42、threads 2。测试可显式降低 `iterations`，正式候选不改变这些值。树模型的目标为 `log(final/current) + log(progress)`，与已有线性外推残差基线一致；解码为 `current * exp(clip(-log(progress)+prediction, 0, 4))`。

全局校正设计为截距、0/1 排名、`2*progress-1`、`exp(-remaining_h/12)`。两个阶段函数也用于阶段交互；加性版本和交互版本共享全局项和类型／乐队主效应。混合乐队沿用输入中的比例，不把混合乐队另建独立组。

校正最小化 `sum_i w_i*(r_i-x_i*beta)^2 + sum_j penalty_j*beta_j^2`。这里每个具有 OOF 校准案例的活动总权重恰为 1；截距惩罚固定 5，其他全局项 10，类型／乐队主效应 30，阶段交互 60。没有从真实标签分布估计收缩强度，也没有验证调参。

Ruling: 本轮采用 CatBoost 骨干加 OOF 收缩校正，而非直接用线性层级模型替换骨干。这样检验上下文是否提供超出单线非线性预测的增益；代价是不能单凭结果区分骨干偏差与上下文效应。阶段结构是每个组两个时间基函数的低维交互，没有实现类型×乐队的完整张量，也不声称验证了该更大假设。

## 隔离与权重

`fit_recipe(config, train_arrays, train_labels)` 只接受注入的训练数组和其案例标签。`predict_recipe(bundle, arrays)` 不接受标签，不读取外部数据，逐案例返回有限终分且不低于当前分数。

内层校准仅在本次调用的训练活动内，按真实开始时间排序，前一半预热，后一半按顺序均分为 3 折。每折骨干只能使用在该折最早活动开始之前严格结束的活动。等于边界的结束时间也排除。两排名和所有前缀始终跟随活动归属；活动 ID 数值不参与时间分组。

Ruling: 这些是校正用的内层折，使用当前注入数组实际出现的活动；它们不改动正式 198 活动归属，也不替代公共 runner 按完整训练活动名单构建的外层诊断折。V2 无前缀活动不会被凭空补样本。若内层折没有已完成历史，记录 `no_completed_history`；其案例仍可由最终骨干预测，仅不伪造 OOF 校准残差。

每次 `fit_recipe` 先计算当前训练数组的全局事件等权向量：每活动权重总和相同，向量均值为 1。内层骨干只切片该向量，不在折内重标定。校正层另行按具有完整 OOF 预测的活动归一化到每活动总权重 1；预热或无历史案例的校正权重为零。最终骨干仍在全部注入训练案例上拟合；不会用最终骨干的训练拟合残差重新训练校正。

每个骨干折从自己的训练行拟合字段类型、数值中位数与类别词表。全缺失数值列填 0。静态上下文词表来自当前训练数组；校正上下文词表仅来自具有 OOF 残差的训练案例。预测阶段不更新词表。未知类型／乐队的组列为零，保留全局效应；部分已知的混合乐队保留已知部分贡献，不把未知比例重新分配给已知组。

## 保存与审计

bundle 可用 joblib 保存，包含最终骨干、预处理器、配置、训练案例 ID 和全局权重。OOF 版本还保留每折模型与预处理器、训练／留出活动及案例 ID、索引、权重、边界时间、OOF 预测和残差、校正权重、词表、系数和惩罚。公共 runner 负责源代码、依赖、bundle 与预测文件指纹及封存。

没有合法 OOF 校准案例时，校正系数全为零，保留完整骨干预测；极小或所有输入特征恒定的训练子集使用事件加权常数残差骨干，避免 CatBoost 无可分特征导致丢失案例。

## 验证记录

开发使用 `tests/test_innovation_hierarchy.py` 中人工构造的 12 个活动，树数降为 6。最初 7 项测试先执行并因实现缺失而失败，再实现并通过。补充核验覆盖加性／交互行为、OOF 目标的加权最优性、非顺序活动 ID、单活动常数回退。

执行命令：`.venv/bin/python -m unittest discover -s tests -p 'test_innovation_hierarchy.py' -v`。本 worker 不与其他 worker 并行运行全库测试；完整测试由主代理顺序执行。

这份说明没有正式性能结论。之后报告必须保留：测试队列曾用于早期探索，不能称为完全未见盲测；元数据为当前回溯快照，缺少历史时点存档。V1 与 V2 时间网格不同，其总体分数差不能称为模型改进；类型或乐队效应不构成因果解释。
