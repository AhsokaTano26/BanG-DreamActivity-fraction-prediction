# V2 两档后续全面实验

用户在上一轮建议核验后明确要求按该方向执行全面 V2 实验。本设计落实既有授权，不另开切分或把生产滚动协议混入 V2。

## 目的与边界

在冻结 `data/temporal_holdout_v2_t1000_t2000` 上比较多时距监督、近期历史特征/偏差校正、表格与时间序列基础模型。数据指纹 `1f76f39af8151bba185496411bbcee064b16a4c5aca5c515c1d957a5056fe854`；训练/验证/测试 2229/1548/1514 案例，实际训练196活动。保持全部案例、时间网格、活动等权、三种子42/123/2026和独立封存评分。

V2 不允许验证/测试终分回灌，也不允许近期活动取得更大训练总权重。因此不执行外部评论中在线回灌后的“5.9%”方案，不把它称为本轮基线。近期权重只作用于合法训练历史的汇总或训练内折外残差汇总，不改变监督训练活动权重。

## 方案与取舍

1. 多时距监督：保留现有小型增长编码器与正增量解码；增加仅来自训练完整曲线的区间增量答案，与终分监督控制组比较。辅助监督按活动归一化，不补造跨大缺口答案。
2. 训练历史适应：固定 CatBoost 控制，增加近期增长/双档比值等历史统计，及训练内前向 OOF 残差的收缩 EWMA。所有训练行的历史排除本期与尚未结束活动；固定验证/测试只能使用训练池。至少保留无校正、收缩、全强度对照。
3. 基础模型：显式锁定 TabPFN v2 权重，尝试 Chronos-2 和 TimesFM。先核对本地依赖、公开权重和推理可行性，再锁定实际可执行配方。若权重/兼容性不可用，保存具体证据并标注未运行，不能用替代算法冒充。不得接受付费服务或使用云推理上传项目数据。

最终预登记配方预算：增长网络6个（直接/进度/双时间轴终分控制，双时间轴辅助强度0.25/1，进度辅助0.25），历史适应5个（控制、近期特征、收缩/全强度EWMA、近期特征加收缩），基础模型4个（TabPFNv2自身曲线/类型乐队背景两个输入对照，Chronos-2与TimesFM2.5两个零样本对照）。新增进度终分控制和TabPFN背景对照在本轮任何正式拟合或验证分数产生之前确定，用于隔离结构与输入差异。

基础模型锁定本地软件版本tabpfn7.1.1（显式v2权重）、chronos-forecasting2.3.2、timesfm2.0.2。TabPFN使用MPS、每种子1个估计器、fit_with_cache，所有原始训练前缀保留，按活动补齐至相同上下文行数；重复行不增加独立样本。时间序列基线只从盲前缀按2h网格重采样并预测到已知结束时刻，稀疏插值跨度保留审计。确切权重提交号/哈希和全部参数另记录在运行清单。

不继续大范围堆叠新的从零训练大网络。基础模型是对照，不预设它们有效。

## 共同接口

新增模块 `analysis/v2_next_{growth,adaptation,foundation}.py`，不得修改已封存模型源文件。

模块接口沿用 `innovation_common.prepare` 的数组字典：`recipes()` 返回预登记配置；`fit_recipe(config, train_arrays, train_labels)` 只接收训练标签和 `train_arrays['history']`；`predict_recipe(bundle, arrays)` 返回全案例最终分数；神经方案用 `predict_members(bundle, arrays)` 返回三种子最终分数。保存模型、配置、依赖/权重版本、训练案例列表以及诊断。

预测入口不能读取答案、SQLite 或完整验证/测试曲线。保存并重载的模型须重放一致，预测不少于当前分数。辅助训练标签不得混入推理数组或预处理。

## 比较、选择与封存

主指标为 event-macro MAPE%。训练内前半活动作预热、后半按实际开始时间分三块；每块只拟合其开始前已结束训练活动。完整拟合后用固定验证集选择配置与预登记组合，不重训。既有 V2 验证已选模型作为可选择保底候选，用其已封存盲预测，不读取旧测试评分选择权重。

组合菜单固定为：每家族验证最佳三种子均值的等权组合；验证最佳新模型与既有模型按25%/50%/75%新模型权重混合。逐种子仅报告，不择种子。

全部候选盲测试预测在独立评分前封存；不能见到测试结果后新增配方。使用现有 `analysis.temporal_evaluate` 独立评分，保留按排名×时点、类型、乐队、缺失覆盖和共同面板的结果。新目录 `analysis/temporal_results/v2_next_20261114`。训练拟合、验证、内部折、测试结果分别呈现。

对模型差异补充活动配对 bootstrap 和连续活动块 bootstrap（块长3与5作为固定敏感性分析）。时间相关区间仍是旧队列内诊断，不构成前瞻保证。

## 实施检查

重点检查辅助目标可用时间/插值跨度、OOF历史排除与目标泄漏、事件等权、基础模型版本和离线运行、缺失/零增长/滞后前缀、同案例完整覆盖、封存后的不可覆盖性。依赖安装只在现有 `.venv` 中进行，不修改已安装轮子、不设置 `KMP_DUPLICATE_LIB_OK`；PyTorch 集成测试保持子进程隔离。

所有旧数据与运行目录保持不变。报告始终注明：旧测试队列已被探索，元数据是缺少历史时点存档的回溯快照，固定验证也存在多轮使用。
