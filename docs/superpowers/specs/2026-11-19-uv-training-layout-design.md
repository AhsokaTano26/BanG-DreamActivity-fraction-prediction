# 网页运行与训练代码分离

用户要求根项目用于调用已有模型并展示网页，完整训练代码置于 `training/`，提供训练入口，统一使用 uv。此前要求只修改本地 main，不提交和推送，仍适用。

## 结构与接口

- 根 `app.py` 默认启动网页；`forecast.py` 保留单线预测兼容入口。
- `production/` 负责观测同步、模型校验、推理、反馈账本与网页。网页配置固定关闭自动拟合，训练由独立入口执行。
- `training/train.py` 提供生产模型拟合、固定协议实验、独立评分和受控旧模块入口。真正拟合代码移入 `training/model_fit.py`。
- `training/analysis/` 保存现有研究模块；`training/legacy/` 收纳旧根脚本。通过可编辑包映射保留 `analysis.*` 等旧导入名，以兼容序列化对象。
- 根 `pyproject.toml` 与 `uv.lock` 管理运行依赖和按需研究依赖，固定生产模型原有 Python 及关键库版本。Docker 同样使用 uv 锁文件。
- 数据、既有运行记录和模型包保持原位和原字节；当前论文仅提供 PDF 的规则继续执行。

## 方案取舍

采用一个 uv 项目与依赖分组，避免两套环境分别解析出不同的模型依赖。训练代码按目录隔离，共用推理所需的特征实现。完整重写预测特征会扩大数值变化风险；只增加入口而保留散落代码无法满足本次目录要求。

## 兼容与证据

先在原环境验证实际生产包并封存技术重放结果。源码位置变化及拟合实现移出会改变指纹；兼容注册只允许此次预先记录的旧完整指纹集合映射到核验后的新完整集合，继续执行依赖、工件、时间与数值重放校验。任意源码修改不匹配该注册时仍拒绝加载。不会覆盖旧模型或把技术重放当作新的精度实验。

验收包括默认网页不触发训练、训练入口可独立拟合和输出包、旧模型技术预测逐值一致、uv 锁定/同步、完整测试、Docker 配置及网页启动检查。计算任务逐项运行，限制数值线程。
