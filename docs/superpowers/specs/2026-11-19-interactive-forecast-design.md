# 命令预测与手动持续服务

用户要求暂停已安装的自动任务，并提供两个运行方式：指定分数线的一次预测；手动启动、持续预测和网页展示。

## 接口

- `.venv/bin/python forecast.py --rank 1000`：默认当前国服活动，联网同步指定排名，使用已训练且满足期初时间约束的模型，输出中文结果后退出。接受 `T1000`；支持 `--json` 和 `--offline`。
- `.venv/bin/python forecast.py serve`：前台启动本地 `127.0.0.1:8765`，单个串行计算任务每900秒复用生产闭环更新19线；网页展示排名选择、当前与预测分数、预测记录及全部排名。Ctrl+C 关闭网页服务和计算子进程。
- 新入口不安装 launchd，也不自动恢复已暂停的任务。

## 实现选择

在现有 Python 项目增加薄入口和标准库 HTTP 服务，复用不可覆盖模型包、活动固定状态和反馈账本。一次预测不训练模型；持续模式复用完整生产协调器，新增历史时按原固定配方训练。另建应用的前后端工程会增加依赖与启动步骤，本次使用独立静态 HTML/CSS/JS。

## 数据与状态

所有既定密集期政策、模型校验、期初历史和开始前反馈守卫继续执行。一次请求只记录实际预测到现有账本，另存 `requests/latest_t<rank>.json`，不覆盖19线的 `latest.json`。缺失或陈旧数据明确显示；联网失败且缓存仍有效时标记降级。服务接口只读，白名单路由，不暴露运行目录、数据库或模型文件。

默认仅本机访问。HTTP 读取和页面交互不触发训练；唯一计算进程与手动预测共享原有周期锁。持续模式退出时终止并等待计算子进程，不遗留定时任务。

## 验收

验证单线选择与新旧活动固定状态、时间守卫、无自动训练、单线输出不覆盖全线结果；验证 HTTP 只读与错误状态；验证 Ctrl+C 后无子进程。运行项目 unittest、真实单线请求以及桌面和手机网页交互。结束时保持所有服务停止。
